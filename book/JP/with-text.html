はじめに · 1

はじめに

会社員をしながら、空き時間に小さなアプリを作っています。飲食店向けの日次衛生チェックと写真証拠を残す「衛生ログ」もその一つでした。要件は大きくないのに、チャットがしんどくなった時期があります。

朝は「写真はいつ必須にするか」を決めるつもりだった。昼すぎにはテーブルのカラム名を直していて、夜にはボタンを右に寄せた差分を見ている。Go した記憶がない。No-Go した記憶もない。ある夜、スレッドを最初から読み直したら、写真必須の条件が言い方を変えて三回出てきた。どれが最終か分からない。ボタンの話のあいだに、「そもそもその画面を出すのか」と迷っている一文が挟まっている。進めているつもりで、決めていなかった。

AI に聞けば返ってくる。それは知っていた。返ってくる場所が一つだと、判断と実装の境目が溶ける。止まっているつもりはないのに進んでいる実感もない、という状態が続いた。ログは長い。決まったことは短い。

混線をほどきたくて、手元の道具を分けてみた。この本でいう三種の神器です。名前は大げさです。中身は地味です。

いま方針と Go / No-Go を置いているのは Grok Bot です。実装コードは書かせない。専門家や Cursor の Project に振る。衛生ログでは、写真必須の条件も日次の締め方も、ここで固めてから先に出しました。「作って」より前に、「やるか」「どこまでか」を残す。Go が出るまで実装側には触らない。夜に読み返すときの迷子が減ったのは、決まったことが短いメモで残るようになったからだと思います。

はじめに

実装は Cursor Projects に渡すようにしました。長い案件の箱、という感覚です。リポ単位で抱えられて、並列にもできる。方針が固まったあとで任せる。司令塔のスレッドにコードを書き始めない。混線していたころは、方針メモのすぐ下に差分が並んでいて、決定と試行錯誤の区別がつかなかった。箱が分かれるだけで、朝の判断が夕方まで残ることが増えました。衛生ログ本体と別件の小さな改善を同じ頭で抱えないためにも助かっています。一つの箱に全部を詰め込むとまた混線する、というのは何度かやってから覚えました。

検証の置き方には pstack を入れています。Cursor のプラグインで、入れ方は /add-plugin pstack のあと /setup-pstack。細かい設定は本編に回します。僕が掴んでいるのは、「動いてから困るより、困る条件を先に書いておく」ための道具、くらいです。衛生ログでも、写真アップロードの失敗を後から直すより、先に検証の置き場を決めておいた方が手戻りが少なかった。完璧なテスト設計の話ではない。困る場所を先にメモする、という感覚に近いです。

三種をきれいに並べると製品紹介になります。言いたいのは優劣ではない。同じチャットに全部を載せない、ということだけです。方針は Grok Bot。実装は Cursor Projects。検証の置き方は pstack。混ぜない。電子書籍の作業とアプリの案件を同じ司令塔で見ている今も、Go 前に実装を始めない一点は変えていません。新規案件を増やしたくなる日はある。増やす前に Go を取る、と決めておくと夜の自分が楽です。

第1章 · 1.2 やってみよう

第1章 三種の神器の全体像
1.2

やってみよう

画面は開きません。紙でもメモアプリでも、手元にあるもので十分です。いま抱えている案件を一つだけ選んでください。大きいものでなくていい。衛生ログでいうと、「写真必須の条件を固める」くらいの粒度で足ります。

紙を三つの欄に分けます。左から「方針」「実装」「検証」。線は雑で構いません。

まず「方針」の欄に、いま決めたいことだけを書きます。やるかやらないか。どこまでやるか。やらない範囲。衛生ログなら、「閉店後のチェックでは写真必須」「開店前は任意」といった一文です。コードの話は書かない。カラム名も書かない。ボタンの位置も書かない。決めることだけです。書けないなら、まだ方針が固まっていない、という事実が残ります。それも十分です。

次に「実装」の欄へ。方針が固まったあとで触る箱を書きます。リポ名でも、Cursor の Project 名でも、「衛生ログ本体の箱」でもいい。いまは名前がなくて構いません。大事なのは、方針の欄に書いたことを実装の欄に移さないこと。混ぜない練習です。

第1章 · 1.2 やってみようの続き

第1章 三種の神器の全体像

最後に「検証」。動いてから困りそうな条件を一行で書きます。衛生ログなら、「写真がアップロードできなかったとき、ログは残すか残さないか」。答えはまだ要りません。困る場所を先に書いておく、という感覚です。pstack の設定はこの段階では触りません。置き場の名前だけです。

三欄が埋まったら、一度読み返します。方針の欄に実装の話が混ざっていないか。実装の欄に Go / No-Go が混ざっていないか。検証の欄が「あとで考える」になっていないか。混ざっていたら、線を引き直して移します。完璧である必要はありません。混ぜない、という一点だけ確認します。

この三欄は、このあとの章でも戻ってきます。Grok Bot に渡すのは方針の欄。Cursor Projects に渡すのは実装の欄。pstack で先に書くのは検証の欄。画面の手順はこれから一つずつ見ます。いまは、手元で分けた、という状態があれば十分です。

図: 司令塔で残した一行を、箱に渡す。範囲外はやらない、と添える。（プレースホルダ）
