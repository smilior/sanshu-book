## テーマ（売る理由）
アプリ事業などで「何を作るか」と「どう実装するか」が同じチャットに混ざると、判断が遅くなる。  
本書は **三種の神器** を事実として整理し、手元でつなぐ手順まで落とす。

### 三種の神器（本書で事実として書くこと）
1. **Grok Bot** … 方針・Go/No-Go・司令塔。実装コードを自分で書かない。専門家や Project に振る。
2. **Cursor Projects** … 長い案件の箱。リポ単位で実装を一任し、並列開発できる。方針を固めたあと、実装は Project に任せる。
3. **pstack** … Cursor のプラグイン（検証ファーストのワークフロー）。`/add-plugin pstack` → `/setup-pstack`。

**実務の芯（僕目線）:** 衛生ログなどのアプリ案件で「方針は Grok Bot、実装は Project」に分けた。電子書籍パイプラインとも共存する司令塔の話として書く。
